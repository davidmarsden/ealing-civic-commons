# Start a Civic Commons

**Status:** Network field guide  
**Home:** https://civiccommons.co.uk/start/

A Civic Commons is a locally rooted public-memory space that connects reporting, records, community knowledge and civic relationships without replacing their original sources.

You do not need permission from Civic Commons to create one. The network is **not a franchise**. The point is to make the model understandable, reusable and accountable while leaving local judgement with the people who know the place.

Before starting, read the **[Charter of the Commons](https://civiccommons.co.uk/charter/)**. The Charter is the shared constitutional layer; this guide is the practical one.

## 1. Start with a place, not a platform

Choose the civic geography you are actually trying to serve: a town, borough, district, municipality, county, neighbourhood cluster or another place that makes sense locally.

Do not begin by choosing software. Begin by asking:

- What public knowledge is scattered or routinely lost here?
- Which decisions and institutions matter locally?
- Which publishers, community groups and official records already exist?
- Which communities or areas are poorly represented in the existing record?
- Who can exercise accountable local judgement about sources and contributions?

## 2. Build a source register

Create a working census before you build a feed.

Useful source families include:

- independent local journalism;
- public-interest and community reporting;
- local authority news, meetings, minutes, decisions and document feeds;
- public notices and consultations;
- neighbourhood, tenants', residents' and civic associations;
- campaigns and issue groups;
- faith and community institutions where their public output has civic relevance;
- local video and public meeting recordings;
- transport, environment, health, planning and other official evidence streams;
- trustworthy local research archives.

Record provenance explicitly. A source register is not a list of endorsements; it is a map of the public information environment.

## 3. Ship the smallest useful Commons

A minimum viable Civic Commons can be modest:

1. a source register;
2. a chronological, provenance-rich aggregated stream;
3. stable URLs for civic items;
4. place/topic/source filtering;
5. an archive so useful records do not vanish with feed expiry;
6. clear links back to original publishers.

That is already useful civic infrastructure. Social features, reviewed knowledge graphs and sophisticated automation can come later.

## 4. Keep original sources canonical

The Commons connects the record; it does not become the record's sole owner.

Do not republish somebody else's work simply because aggregation makes that convenient. Preserve the title, publisher, date, canonical destination and enough context to help people understand why a record matters.

Where preservation is necessary, distinguish clearly between source material, metadata, archived snapshots and Commons-added context.

## 5. Prefer chronology to engagement ranking

A Civic Commons is not an attention product.

Default to chronological presentation, place, source, topic and reviewed civic relationships. Do not make outrage, clicks, behavioural profiling or advertising value the organising principle.

## 6. Add civic memory before adding a social network

Feeds are transient. Civic questions are not.

Create persistent item identities and archive normalised records early. This makes it possible to connect later reporting, official records, corrections and contributions to something stable.

A useful sequence is:

**Discover → preserve → connect → invite contribution.**

## 7. Moderate additions; do not crowdsource truth

Residents should be able to submit corrections, evidence, related sources and local context.

Keep a review membrane between suggestions and reviewed civic knowledge. Public additions should preserve provenance and an audit trail. Private submitter information should stay private.

## 8. Add a reviewed civic graph only when it helps

People, organisations, places, issues, documents and events can become durable civic objects when doing so makes the record easier to understand.

Do not create entities merely because the software can. A useful public entity needs identity, description, provenance and an authoritative source or website where one exists.

Historical and current identities should not be silently flattened together.

## 9. Use local identity beneath the network identity

The **Open Gate** is the Civic Commons network mark. A local Commons can and should have its own place identity.

The Ealing implementation uses a rooted oak for the borough and local landmarks for town lenses. Another locality should develop symbols that belong to its own place rather than copying Ealing's.

Local branding should sit beneath the shared network idea, not turn every implementation into a visual franchise.

## 10. Give people a route back to the network

A local Commons should have its own canonical domain or subdomain and a visible route to **https://civiccommons.co.uk/**.

The current reference pattern is:

- `civiccommons.co.uk` — network front door;
- `ealing.civiccommons.co.uk` — canonical Ealing implementation;
- town-specific entry points — lenses or shortcuts into the local Commons, not independent data silos.

A local doorway should never become a navigational dead end.

## 11. Publish the rules and architecture

Document:

- what sources are included and why;
- how moderation works;
- what data is stored;
- what is public and private;
- how canonical URLs work;
- how archives and exports work;
- how local governance decisions are made;
- what parts of the system depend on external services.

The public should be able to understand how the Commons works without reverse-engineering it.

## 12. Design for exit

Assume volunteers leave, organisations change and services disappear.

Prefer exportable data, documented schemas, ordinary web URLs, RSS, accessible documents and replaceable infrastructure. Keep the project useful when one vendor or platform fails.

## Reference implementation: Ealing

**[Ealing Civic Commons](https://ealing.civiccommons.co.uk/)** is the first working implementation and therefore the current reference case, not a mandatory template.

Its implementation documents are public precisely so other places can see the choices, mistakes and trade-offs:

- [Source Register](https://ealing.civiccommons.co.uk/documents/source-register)

Treat these as evidence from one live implementation. Reuse what helps; replace what does not fit your place.

## A practical first month

**Week 1 — map the place.** Define scope, identify source families, make a source register and write down obvious coverage gaps.

**Week 2 — aggregate carefully.** Start with the most reliable public feeds and pages. Preserve publisher identity and canonical links.

**Week 3 — make memory durable.** Give items stable identities, add an archive and test whether older records remain findable.

**Week 4 — invite scrutiny.** Publish your source register, architecture and moderation rules. Ask local publishers, civic groups and residents what is missing or misleading.

Do not wait for the perfect platform. A small, transparent Commons that remembers useful things is better than an elaborate civic system that never opens.

## The test

Before calling something a Civic Commons, ask:

- Does it make local public knowledge easier to find and revisit?
- Can readers see where information came from?
- Does it preserve original publishers rather than erase them?
- Is participation reviewed rather than popularity-ranked?
- Is private data handled conservatively?
- Can it survive the loss of a platform or service?
- Is it genuinely shaped by the place it serves?
- Can somebody understand how it works?

If yes, you are already building one.

**Build locally. Connect openly. Remember civically.**
